# Retail & E-commerce: Customer Segmentation and Churn Prediction

Axlero DA Internship - **Project 1**. Segments D2C customers with RFM + K-Means and predicts
who will churn in the next 60 days, then packages the results for a BI dashboard.

| Success metric (from PRD) | Target | Result |
|---|---|---|
| Data integrity | < 5 % of rows dropped | **0.50 %** (duplicates only; missing values imputed, outliers capped) |
| Model performance | ROC-AUC >= 0.75 | **0.914** test (CV 0.913); **0.797** on still-active customers |
| Actionability | >= 4 segments with recommendations | **4** segments, each with a marketing playbook |

> Data is **synthetic** (generated by `src/dataset.py`, seed 42) because no client data was provided.
> Swap in real CSVs with the same columns in `data/raw/` and re-run the pipeline.

## Quick start
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# PostgreSQL (any local instance). Override with DATABASE_URL if needed:
#   postgresql+psycopg2://USER:PASS@localhost:5432/retail_churn
createdb retail_churn

python -m src.dataset          # generate raw CSVs + load into PostgreSQL
python -m src.run_pipeline     # SQL extract -> clean -> RFM -> K-Means -> churn model -> BI tables
python -m src.build_dashboard  # standalone interactive dashboard (dashboard/churn_dashboard.html)
pytest -q                      # unit tests (leakage + cleaning)
```
Notebooks (`notebooks/`) run top-to-bottom in order `1.0 -> 4.0` and write the same artifacts.

## Method in brief
1. **Week 1 - Ingest/EDA:** CSV -> PostgreSQL; SQL de-dup view and flattened user-level query;
   programmatic cleaning (median impute, winsorise at p99, flag returns).
2. **Week 2 - RFM + K-Means:** `log1p -> StandardScaler -> KMeans`; k chosen by elbow + silhouette
   with k >= 4 (best silhouette -> k = 4).
3. **Week 3 - Churn model:** time-based snapshot (features before 2025-10-31, label = no order in the
   next 60 days) so recency is not a label proxy. Logistic Regression and Random Forest, each with class
   weights or SMOTE (SMOTE inside the CV pipeline). Selected: Random Forest + class weights.
4. **Week 4 - BI:** live base scored as of 2026-01-01; Power BI/Tableau tables exported.
